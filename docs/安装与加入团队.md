# 安装 Research OS，加入团队

这份说明写给不写程序的研究者。照着做，大约需要半小时，其中一大半是等电脑下载。

分两部分：

- **第一部分：成员**。别人（PI）请你一起做项目，你在自己的 Mac 上装好 Research OS，加入这个项目。
- **第二部分：PI**。你是项目的负责人，要把项目共享给成员。

两部分之后是每天怎么用、遇到「两边都改过」怎么办，以及 Research OS 从来不做的事。

## 开始之前

你需要：

1. 一台 Mac。
2. 一个个人版的 Microsoft 账号（OneDrive 用它登录）。PI 会把文件夹共享给这个账号的邮箱。
3. 能上网。

有几步要在「终端」里输入命令。打开终端的办法：按住 Command 键再按空格键，输入「终端」，按回车。命令都放在灰色方框里：整行复制，粘贴到终端里，按回车，等它做完（重新出现可以输入的那一行）再做下一步。终端里的英文提示不用全部看懂，这份说明会告诉你该看哪一句。

## 第一部分：成员

### 1. 安装 OneDrive 并登录

1. 打开 App Store，搜索「OneDrive」，安装 Microsoft OneDrive。
2. 打开 OneDrive，用你的个人 Microsoft 账号登录。
3. 问到 OneDrive 文件夹放在哪里时，用默认的位置即可。
4. 完成后，访达（Finder）左边栏的「位置」下面会出现「OneDrive」。

### 2. 安装苹果的命令行工具

Research OS 要用苹果的命令行工具把自己做成一个 Mac 应用，安装程序也要用它从 GitHub 下载 Research OS。在终端里输入：

```
xcode-select --install
```

1. 屏幕上会弹出一个窗口，问是否现在安装命令行开发者工具。点「安装」，再点「同意」接受苹果的许可协议。
2. 等它下载并安装完（几分钟到半小时不等），点「完成」。
3. 如果终端里出现 `already installed` 字样，说明这台电脑已经装过，直接做下一步。

### 3. 安装 uv

uv 是一个安装工具，它会自己带上 Research OS 需要的 Python。macOS 自带的 Python 版本太旧，Research OS 用不了，所以你不需要、也不要另外去装 Python。在终端里输入：

```
curl -LsSf https://astral.sh/uv/install.sh | sh
```

1. 最后几行出现 `everything's installed!` 就是装好了。
2. 关掉终端（在终端里按 Command 加 Q），再重新打开一个终端。这样终端才找得到刚装好的 uv。
3. 输入下面这行检查一下，它会显示一个版本号，例如 `uv 0.10.4`：

```
uv --version
```

### 4. 安装 Research OS

在终端里输入：

```
uv tool install git+https://github.com/LinyingL/research-os
```

1. 第一次安装时，uv 会先下载 Python，再下载 Research OS，需要一两分钟。
2. 最后几行里出现 `Installed 2 executables: rce, researchos` 就是装好了。
3. 如果最后几行里有 `is not on your PATH`，再输入下面这行，然后关掉终端重新打开：

```
uv tool update-shell
```

4. 如果没有出现 `Installed 2 executables: rce, researchos`，而是出现了 `Git operation failed`、`could not read Username` 或 `Installed 1 executable: rce`：说明能用的新版本还没有放到 GitHub 上。不要换别的地址，也不要往下做。把终端里最后几行拍照或复制下来，发给 PI。如果出现的是 `Installed 1 executable: rce`，先输入下面这行，把装上的旧版本去掉，等 PI 通知以后再做这一步：

```
uv tool uninstall rce
```

### 5. 把 Research OS 放进「应用程序」

在终端里输入：

```
researchos app
```

它会在你个人文件夹里的「应用程序」文件夹中做出「Research OS.app」，最后一行是 `双击 Research OS.app 即可打开研究地图`。这一步要编译，需要几秒到一分钟。做完以后就不再需要终端了。

### 6. 第一次打开 Research OS

1. 按住 Command 键再按空格键，输入「Research OS」，按回车。也可以在访达里，从菜单「前往」选「个人」，打开「应用程序」文件夹，双击「Research OS」。
2. 想以后方便打开：在程序坞里右键点 Research OS 的图标，选「选项」，再选「在程序坞中保留」。
3. Research OS 第一次读你「文稿」文件夹里的文件时，macOS 会问是否允许「Research OS」访问「文稿」文件夹中的文件。点「好」或「允许」（按钮的字样随 macOS 版本不同）。如果点了「不允许」：打开「系统设置」，点「隐私与安全性」，再点「文件和文件夹」，找到 Research OS，打开「文稿文件夹」的开关。
4. 如果 macOS 问是否允许 Research OS 访问 OneDrive 里的文件，同样点「允许」。

第一次打开时还没有项目，页面上有两个按钮：「添加项目…」和「从公盘加入项目…」。

### 7. 填写「我是谁」，把公钥发给 PI

1. 点「从公盘加入项目…」。右边会打开一个面板。
2. 在「1. 我是谁」里填你的名字，和你 OneDrive 账号的邮箱（PI 会把文件夹共享给这个邮箱；它也是你在团队里的编号），点「保存」。
3. 在「2. 我的公钥」里点「生成我的公钥」。会出现一行以 `ssh-ed25519` 开头的文字。
4. 点它下面的「复制」，粘贴到邮件或微信里，连同你的邮箱一起发给 PI。如果按钮变成「请手动选中复制」：在那一行文字上点一下（会整行选中），按 Command 加 C 复制。

公钥可以放心发出去：它只用来让 PI 确认提议真的是你发的。和它配对的私钥只在你这台电脑上，不会离开。

发完以后可以点面板右上角的「关闭」，等 PI 的邀请。项目打开以后，这些内容都在左边栏的「成员」一栏里。

### 8. 接受 PI 的两个共享邀请

PI 把你加入团队以后，会在 OneDrive 里给你共享两个文件夹，你会收到两封 OneDrive 的邮件：

- 「已发布」：项目的正式版本，你**只能查看**。
- 一个用你的邮箱命名的文件夹，例如 `wang@example.com`：这是你自己的提议文件夹，你**可以编辑**。

两个文件夹要分别加到你自己的 OneDrive 里，它们才会同步到你的电脑上。每一封邮件都这样做：

1. 在邮件里点「打开」。浏览器会打开 OneDrive 网页版；如果要求登录，用你的个人 Microsoft 账号登录。
2. 在打开的文件夹页面上方，点「添加到我的文件」。有的版本写作「添加快捷方式到我的文件」，是同一个按钮。
3. 如果找不到邮件：在 OneDrive 网页版左边点「共享」，再点「与我共享」，在那个文件夹上右键点，选「添加到我的文件」（或「添加快捷方式到我的文件」）。

### 9. 等两个文件夹同步到电脑上

1. 打开访达，点左边栏的「OneDrive」。几分钟内会出现「已发布」和用你的邮箱命名的那个文件夹。
2. 在两个文件夹上分别右键点，选「始终保留在此设备上」。Research OS 不读只在云端、还没有下载到电脑上的文件。
3. 等文件夹旁边的云朵图标都变成对勾，屏幕顶端菜单栏里 OneDrive 的图标不再显示正在同步。

### 10. 选好两个文件夹，核对 PI 的指纹，加入

1. 回到 Research OS，点「从公盘加入项目…」。如果已经打开了别的项目，点左边栏上方「项目」下面的项目名，在打开的菜单里选「从公盘加入项目…」。
2. 在「3. 公盘和工作副本」里，分别点「选择…」：
   - 「公盘文件夹，或 PI 共享给你的「已发布」文件夹」：选 OneDrive 里的「已发布」。
   - 「你自己的提议文件夹」：选 OneDrive 里用你的邮箱命名的那个文件夹。
   - 「工作副本放在哪里」：你自己的这份项目放在哪里。在弹出的窗口里进入「文稿」，点「新建文件夹」，起一个名字，例如「汇率论文_我的副本」，选它。它必须是一个新的、空的文件夹；不要把它放在 OneDrive 里面。
3. 点「查看」。Research OS 会先检查：「已发布」里有这个项目经过 PI 签名的版本；你能写入自己的提议文件夹。到这时为止，它什么都没有写入。
4. 页面上会显示「PI 公钥指纹」，是一串以 `SHA256:` 开头的字母和数字。打电话给 PI，或者用和发公钥不同的方式（例如当面）请 PI 念出或发来他的指纹，逐个字符对一遍。
5. 完全一致，再点「核对无误，加入」。如果不一致，不要加入，先告诉 PI。

加入以后，Research OS 会打开你的工作副本，扫描一遍，并显示「成员」一栏。以后它只接受用这把钥匙签名的版本。

### 11. 同步

1. 在「成员」一栏的「公盘与同步」里，可以看到你的工作副本基于第几版，以及你选好的两个文件夹。
2. 点「同步」。如果 PI 在把你加入团队之后已经发布过，它会说「已经是最新的官方版本」；否则等 PI 发布以后再同步一次。
3. 「团队」里出现你的名字，你就是成员了。

## 第二部分：PI

### 1. 安装

和成员一样，做第一部分的第 1 步到第 6 步：安装 OneDrive 并登录，安装命令行工具、uv 和 Research OS，`researchos app`，第一次打开。请成员安装之前，你自己先装一遍：第 4 步没有出现 `Installed 2 executables: rce, researchos`，就先不要请成员安装。

### 2. 打开你的项目

如果 Research OS 里还没有这个项目：点「添加项目…」，点「选择文件夹…」，选你的项目文件夹。Research OS 先列出它会读取哪些文件、会写入什么；看过以后点「加入并扫描」。

### 3. 在「成员」里设好你自己

1. 点左边栏的「成员」。
2. 在「我是谁」里填你的名字和你 OneDrive 账号的邮箱，点「保存」。
3. 在「开始协作」里点「建立成员名单」。你就是这个项目的 PI；这台电脑上会生成一对签名密钥，私钥不离开这台电脑。

请把签名密钥所在的 `keys` 文件夹备份一份，例如拷到 U 盘上（在访达里，从菜单「前往」选「前往文件夹…」，输入 `~/.researchos/keys`，按回车）。私钥丢了没有办法找回：换一把新钥匙，所有成员都要重新核对指纹。

### 4. 选好公盘文件夹并发布第一版

1. 在访达里打开「OneDrive」，新建一个文件夹给这个项目的团队用，例如「汇率论文_团队」。它不能在项目文件夹里面。
2. 在这个文件夹上右键点，选「始终保留在此设备上」。
3. 回到 Research OS 的「成员」，在「公盘」里点「选择…」，选这个文件夹，点「设为公盘」。
4. 点「发布」。Research OS 会在这个文件夹里建好「已发布」，写入第一版。

### 5. 加入成员

成员把公钥和邮箱发给你以后（第一部分第 7 步）：

1. 在「成员」的「添加成员」里，填成员的邮箱和名字，把成员发来的那一行公钥文字粘贴到「公钥文字」里（如果对方发来的是一个文件，点「公钥文件」旁边的「选择…」选它）。
2. 点「加入团队」。Research OS 会在公盘文件夹里建好这位成员的提议文件夹「提议/成员的邮箱」。
3. 再点一次「发布」。成员加入或同步以后，就会看到自己在团队里。

### 6. 在 OneDrive 网页版里共享两个文件夹

这两项共享权限保证了「只有 PI 能批准」是一条规则，而不只是一个约定。每位成员都要做一次：

1. 用浏览器打开 OneDrive 网页版（onedrive.live.com），用你的个人 Microsoft 账号登录。
2. 在「我的文件」里打开你的公盘文件夹（例如「汇率论文_团队」）。
3. 共享「已发布」，只能查看：
   1. 把鼠标移到「已发布」上，点它左上角的圆圈，选中它。
   2. 点页面上方的「共享」。
   3. 在弹出的窗口里，点权限设置（铅笔图标或写着「可以编辑」的地方），改成「可以查看」。
   4. 输入成员的邮箱，点「发送」。
4. 共享成员自己的提议文件夹，可以编辑：
   1. 打开「提议」文件夹，选中用这位成员的邮箱命名的文件夹。
   2. 点「共享」，权限选「可以编辑」。
   3. 输入**这一位**成员的邮箱，点「发送」。

不要把整个公盘文件夹或整个「提议」文件夹共享出去，也不要把一位成员的提议文件夹共享给别的成员。

### 7. 把你的指纹告诉成员

1. 在「成员」的「我的公钥」里，「指纹：」后面是一串以 `SHA256:` 开头的字母和数字。
2. 成员加入时会打电话或当面问你，念给他听，或者用和他发公钥不同的方式发给他。

## 每天怎么用

### 成员

1. 打开 Research OS，在「成员」里点「同步」，从最新的正式版本开始。
2. 在你的工作副本里照常工作：脚本、数据、尝试表、变量卡。
3. 想把改动交给 PI：点左边栏的「提议」，在「提交提议」里选一种（「新的尝试」「改判」「变量定义」「只有文件」），用一句话说明，点「查看将要发送的内容」。看清楚要发送哪些文件，可以勾选加上或去掉；改了勾选，先点「按勾选的文件重新查看」，再点「发送提议」。一个文件如果曾在被退回的提议里，旁边会提醒你先看看退回的理由。也可以从菜单「文件」选「提交提议…」。
4. 提议要等 OneDrive 把它同步到 PI 的电脑上，PI 才看得到；PI 的答复也一样要等同步，通常几秒到几分钟。「提议」里能看到每份提议的状态：「提议中」「已批准」「已退回」（带着 PI 写的理由）。PI 批准以后，你的改动标着「已批准，待同步」，同步一次就成了正式版本。
5. 你写的笔记、对连线的判断、「关联文件」和「补上来源」，会在下一次同步时自动发送给 PI，不需要批准。

### PI

1. 「提议」里是等你处理的提议。打开一份，可以看到批准以后正式版本会怎样变化。
2. 三种答复：「批准并加入」（改动写入正式版本，并自动发布一版）；「退回并说明」（必须写理由，成员会看到）；「讨论」（写一句话，提议保持打开）。
3. 你自己改了正式版本以后，在「成员」里点「发布」（或从菜单「文件」选「发布」），成员同步以后就会看到。

## 两边都改过同一个文件时

Research OS 从不替你合并两个人的改动，而是把两份都给你看，由人来决定。

- **PI 看到「两边都改过」**：成员上次同步以后，你也改过这个文件，这份提议现在不能批准。退回它，请成员先同步，再重新提议。尝试表按行比较：只有这份提议自己的那一行（或新的一行要用的编号）在正式版本里变过，才算两边都改过；你改别的行不影响它。
- **成员同步时遇到两边都改过的文件**：你的那一份不会动，官方的一份放在旁边，名字是「原名.official.扩展名」，例如 `16-build.official.py`。在「成员」的「放在旁边的官方版本」里可以看到两份的不同。比较以后，把对的内容留在原来的文件里，删掉 `.official` 那一份（删掉以后，「放在旁边的官方版本」里的这一项也会消失），再重新提议。

## Research OS 从来不做的事

1. 不合并两个人对同一个文件的改动。
2. 不修改公盘里已经写好的任何东西。每一个版本、提议和答复都用新名字写一次，以后不再改动。OneDrive 生成的冲突副本和没有写完的内容，它只报告，不读取。
3. 不连接 PI 的电脑，也不自己联网。团队之间唯一的联系是 OneDrive 同步的那两个文件夹。
4. 不接受无法核对签名的版本。不是 PI 签名的版本会被拒绝，保留最后一个核对通过的版本。
5. 不在你看清楚之前发送任何东西：提议发送前，先列出它会带上的每一个文件。

## 以后更新 Research OS

在终端里输入下面两行，第二行会在需要时重新做好「Research OS.app」：

```
uv tool upgrade researchos
researchos app
```

如果更新改动了应用本身，macOS 会再问一次是否允许访问「文稿」文件夹，点「好」或「允许」。
