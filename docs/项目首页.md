# 项目首页

适用于 Research OS **0.5.0**。

点击“新建项目…”，填写名称并选择保存位置，即可进入项目首页，直接写研究问题和计划。
软件会自动准备一张空白尝试表，之后需要时再开始记录尝试；不用先导入历史。

已有研究文件夹仍用“添加项目…”打开。浏览首页不会修改原有文件；第一次保存研究问题与计划时才
建立写作文件，原来的尝试表保持不变。
如果还没有尝试表，第一次点击“新增尝试”时会自动创建空表和设置，然后打开表单。
已有文件会保留，不需要先导入表格或手动编辑配置。

## 写研究问题与计划、笔记和结果记录

内容可以自由写，随时修改。点击“保存”，或在写作区按 Command-S。“预览”可以查看
标题、列表、表格和本地图片。

“新建笔记”适合想法、讨论和待解决的问题；“记录结果”用来把图表、发现和解释放在一起。
这些记录可以独立存在，也可以按需关联研究尝试。笔记和结果记录按最后一次改动排列，最新的在前。
文档的标题就是文件里的第一个标题：只有你输入的标题和文件显示的不一样时，Research OS 才会往文件里写标题，
不论屏幕用的是哪种语言。

你自己放进 `research/notes/` 或 `research/results/` 的 Markdown 文件，不论叫什么名字，也会列出来，
同步服务在文件旁边留下的副本同样如此；可以像其他文档一样打开、保存。`research/` 里的文件不会被当作论文草稿读：
笔记里的数字不会变成论断。

下方的任务清单可以填写负责人和日期，也可以只记一句接下来想做的事。任务没有固定
顺序，可以修改、完成或移除；不用先完成任务才能继续写作或记录研究。

## 引用外部工具产生的文件

继续用 Stata 等工具编辑代码、运行分析。把结果保存在项目目录后，展开“引用文件或
尝试”，点击“刷新文件”，选择文件后点“插入引用”。支持的图片可以直接预览，文件仍放在
原处，不会再复制一份。研究尝试按编号排列（2 在 10 之前）。项目文件多于 500 个时，列表只显示前 500 个并会说明；
手写链接指向这 500 个之外的已有文件，在预览和“提交修改”里同样有效。

引用表示你选择了这个文件，不代表软件已经确认脚本运行过或生成了某项结果。

## 让 AI 执行者做任务

在任务区点“输出目录”，可以设置代码、数据、图、表、文献、文稿、变量草稿和过程文件的保存位置。
默认优先沿用常见的已有目录。保存设置不会移动文件，也不会预先创建空目录；每次运行会
取得一份当时的目录设置，后续修改供新的运行使用。

**过程文件。** 输出是你要读、要再用的文件：图、表、供后续工作用的数据集、文档、文献导出、变量草稿，
以及复现其中任何一项所需的代码。执行者只为完成这次任务而写的东西都是过程文件：一次性的探查和自检脚本
及其输出、核对用的文件、下载来的第三方源码、临时数据和缓存。它们放进这项任务的“过程文件夹”，默认是
`work/<日期>-<任务名>/`，例如 `work/20261025-价格核对/`：日期是任务第一次运行的那天，任务名取任务的第一行（会缩短）。同一项任务以后的运行
（回答、打回、重新运行）用同一个文件夹。文件夹由执行者在需要时自己建，Research OS 不预先创建。
索引会跳过过程文件夹，里面的文件不算输出，里面的数据文件也不受保护，所以这项任务以后的运行可以改写自己的过程文件。
这个位置要单独放：不能与其他位置相同，不能包含其他位置，不能位于其他位置里面，也不能放在 `research/` 下；
这样的选择会被拒绝。如果没有可用的文件夹，“输出目录”会请你为过程文件选一个，选好之前运行不会开始。

任务完成时，AI 要列出最终文件的类型和路径。软件检查位置、文件是否存在和支持的格式，
再放到对应视图。图和普通的 CSV/TSV 表格可以预览；文献导出里的摘要进入文献列表，PDF 也会
列出文件入口。数据和表格文件可以带一个压缩后缀（`.gz`、`.bz2`、`.xz`、`.zst`，例如 `prices_long.csv.gz`），
按它里面的文件类型登记，没有预览；保护运行前就有的数据文件、不让执行者改动的那条规则，目前不包括压缩过的文件。
登记关联的是任务和文件，不代表软件证明分析运行过或认可了研究结论。
“图表与论断”“数据与代码”“文献”“变量”里已登记的文件按任务分组，每项任务一个标题：这项任务结果记录的第一个标题
（没有就用任务的第一行；任务已不在清单里时写“任务已移除”）、产出这些文件的那次运行的日期，以及一个“打开结果”，
点它会回到项目首页并打开这项任务的结果记录。每一行不再重复任务名；只有它的日期与标题上的不同时才写出自己的日期。

**任务输出。** 有结果记录的任务，在任务行的“任务输出”里列出它的文件，随任务的其他详情一起折叠。
已登记的文件按类型分组，点文件名在文件面板里打开，图有小预览，每个文件旁都有“移除登记”。“过程文件”这一组
在你展开之前只显示文件数；其他超过 8 个文件的组只显示前 8 个，其余用“另外 N 个”展开。你展开过的，
任务行重新画出来时仍保持展开。每次运行结束后，
Research OS 把这次运行新建的文件分一分类：它自己写的记录、已为这项任务登记的输出、过程文件夹里的文件、缓存，
以及其余的。这项任务在这台电脑上没有撤回的所有运行（一问一答是同一段对话的两次运行），如果还留下其余的文件，
这一行接着写明，例如“3 个新文件未登记”，旁边的“登记…”会把它们列出来让你核对（见下）。最后是过程文件夹的路径和里面的文件数。

**登记和移除。** 登记在两份核对列表里进行（见下）：任务行里的“登记…”，和“输出目录”里的“补登记以往运行的文件…”。
列出的是运行新建、还没有人登记的文件。这样的文件放在哪里都可以登记，不论在输出目录里还是项目里的别处，类型可以选格式允许的任何一种；
“过程文件”不限格式。记录文件、`research/notes/` 和 `research/results/` 下的文件，以及 `.researchos/` 不会列出，也就不能登记；
你自己写的、没有哪次运行新建过的文件，同样不能在页面上登记。
“移除登记”会先问一声，文件本身留在原处。登记过的文件如果已经不在，这一行仍然保留，标为“文件已不在”，
方便你把它移除；文件只在云端、这台电脑读不了的，标为“文件只在云端”，仍算已登记。你登记的过程文件只显示在
任务行里，各个视图不列出。一项任务最多登记 1,000 个文件，路径很长时更少（一份记录最大 200 KB）；放不下的登记
会整批被拒绝，并提示少登记几个或先移除一些。运行新建、又登记为文档的文件（执行者登记的，或你从核对列表里登记的）
不会被当作论文草稿，里面的数字不会变成论断；运行前就有、被执行者改过的草稿仍是草稿。

**补登记以往运行的文件。** 早先的运行里执行者新建的文件，没有登记过。“输出目录”里的“补登记以往运行的文件…”
（任务行里的“登记…”列这项任务所有没有撤回的运行的）会把其中还在的文件列出来，按任务分组，写明运行日期和执行者。
从这里登记的文件，日期按创建它的那次运行算。
已撤回的运行、没有结果记录的任务、记录文件、缓存、运行自己过程文件夹里的文件和已登记的文件都不列。
每个文件按所在的文件夹和名字给出建议类型：在 `checks`、`logs`、`tmp`、`sources` 等文件夹里的文件和 `.log` 文件建议登记为过程文件，
图片为图，`.bib` 为文献，代码、数据、文档按格式。看不出类型的文件，选的是“不登记”。改好类型、取消不想登记的勾选，
再点“登记所选”；在这之前不会写入任何东西，也不会移动任何文件。某个文件被拒绝时（列出之后它改过或已不在，
或者不符合所选类型，例如读不出任何文献的文献导出），提示会写明是哪个文件，你就知道该取消哪个勾选。
一次最多列出 5,000 个文件，登记后再打开可以看到其余的。

变量定义使用现有的 TOML 格式，先显示为草稿。点击“导入为变量草稿”才会建立定义卡；
已有确认版本时建立下一版草稿，已有未处理草稿时不会覆盖。导入不等于确认，采用哪一版
仍由你在定义卡里决定。

目录设置保存在 `research/folders.json`，保存时八个位置都会写入。每份任务报告在 `research/results/` 中都有自己的
`<报告编号>.outputs.json` 登记文件，由软件维护；你的登记和移除也写在这些文件里。不同任务可以分别撤回；提交任务修改时，
相关输出文件和登记信息也会加入原有的团队审阅，成员改过的登记即使任务本身没变，也会列在那里。

任务的负责人可以选这台电脑上的 AI 执行者：Codex、Claude Code、DeepSeek Harness，或通过 OpenCode 连接的模型。
它是真的去做这项任务，不只是写一份草稿。

**准备。** 先安装选用的程序并登录。再安装带可选 MCP 组件的
Research OS（见 [README](../README.md#optional-ai-agents)）；没有安装时，点“运行”会
告诉你缺什么。在任务区点开“AI 执行者”，软件会显示是否找到了各个程序及其版本；找不到
就填写程序的完整路径。选择程序和「模型版本」即可添加。Codex 的列表显示 `gpt-6.1-sol` 这样的完整 ID，
可以点「刷新模型列表」重新读取。Claude Code 按 Sonnet 5.5、Opus 4.6 等具体版本列出，
旁边显示完整 ID。新模型需要较新的 Claude Code，可用 `claude update` 更新。
Claude 列表采用官方文档列出的版本，账号能否使用由程序在运行时检查。
选择「手动填写完整 ID…」可以指定版本或快照，
也适用于 Claude Code 的完整模型 ID 和 OpenCode 的 `提供方/模型`。选定的 ID 会原样
交给程序；账号能否使用该模型由程序检查。

Codex 使用 `codex login` 的登录状态，也可以使用 macOS 桌面 App 自带的 CLI。
通过 ChatGPT 登录时不需要填写 API Key。GPT-5.5 已不支持 ChatGPT 登录，仍可通过
API 认证使用，具体见 [Codex 模型说明](https://learn.chatgpt.com/docs/models)。
通过 OpenCode 使用本地模型，做法相同。

**推理强度。** 添加执行者时，可以在模型旁选择强度，也可以在已添加的执行者一行更改。
「默认」沿用执行程序的配置。Claude Code 和 DeepSeek Harness 按支持的模型版本提供
档位，Codex 从当前模型列表读取；没有已知可用档位的模型（包括 OpenCode）不显示这项。
运行记录会保存所选设置。同一次对话里的回答和打回沿用原设置；重新运行才使用当前选择。

DeepSeek Harness 支持官方桌面端自带的 `dsh`，软件会在 `/Applications` 和
`~/Applications` 下寻找，也可以使用单独安装的 `dsh`。选「账户」模型使用 Harness
桌面端登录，选「API Key」模型使用 Harness 配置的密钥。建议列表包含
`deepseek-flash` 和 `deepseek-v4-pro`，能否使用由 Harness 在运行时检查。
手动填写时包含认证方式：`deepseek-account/模型ID` 或 `deepseek-official/模型ID`。
任务通过官方 headless 接口运行，回复问题时继续同一段会话。每次任务使用临时配置，
不改桌面端配置；仅在桌面端启用的插件和 Office 资源不会加载。

**运行。** 把任务的“负责人”选成这个执行者，点击“运行”。每次打开页面后，第一次运行某个
执行者时，软件会先说明内容会发到哪里，执行者会直接修改项目里的文件，以及撤回不了什么（它安装的软件、下载的内容、
git 里的操作，以及项目文件夹以外的一切）。它还会列出项目里超过 16 MB 的文件（最大的十个，其余给出个数）：
这些文件运行前不会备份，改动后无法撤回。任务上会显示状态：准备中、
运行中、等你回答、已完成、未报告、失败、已停止、已中断，或越过了限制（见下）。同一个项目一次只运行一个；点“停止”会
结束它和它启动的所有程序。运行超过时间限制（默认两小时，可以在同一处修改，Claude Code 还可以设花费上限）会被停止；退出软件时也会停止。

**它会做什么。** 执行者在项目文件夹里工作：读你的文件、写代码、运行 Python、R 或
Stata、安装软件包、下载数据、写笔记。运行前它会被告知：各类文件放在哪里（就是“输出目录”里的位置）、
哪个过程文件夹和子目录名属于这项任务、过程文件放进过程文件夹，以及不要在 `research/` 下新建任何东西，那里只有
Research OS 自己写。它结束时留下仍在运行的程序会被一并结束。做完后它写一份结果记录，把任务标为完成并关联这份
记录；点“打开结果”可以查看。这份记录就是这项任务唯一的报告：你要求的文档（方案、评审、文稿）作为输出放进文档目录，
结果记录保持简短，写结论、关键数字和先读什么。执行者在报告里要紧的地方写出文件名，但不另附输出清单：
Research OS 会在记录末尾追加“已登记的输出文件”一节。
在预览里，用代码样式写出的文件路径可以点开那个文件，从项目文件夹出发（而不是从记录自己所在的文件夹出发）写的链接也可以；记录本身不会被改写。
记录里的图表和数字应当来自它实际运行的结果，请像核对同事的工作一样核对。

**它不能做什么。** 它不会替你做研究判断：不写尝试表里的判决和结果，不确认或否决关联，
不碰 `.researchos/`。不会提议、批准、发布、同步，不会推送到 GitHub，也不会改变 git 的
状态（提交、重置、切换分支等）。运行前就有的数据文件（`.csv`、`.tsv`、`.xlsx`、`.xls`、`.parquet`、`.feather`、`.rds`、`.rdata`、`.dta`、`.sav`、`.json`、`.h5`、`.pkl`、`.sqlite`、`.db`、`.npy`、`.npz`、`.mat`、`.sas7bdat`、`.jsonl`、`.pickle`；`package.json` 和 `package-lock.json` 不算数据文件）它不改也不删，
也不移动或删除装着这些文件的文件夹，新数据写成新文件。除了通过它自己的工具，它也不直接编辑
`research/tasks.json`。Research OS 用两种办法保证这些：程序支持时，在每一步之前检查；
每次运行前后再对比项目文件夹。如果仍有改动越过了界限，会用警示色排在最前面，标为
“越界改动”，旁边有“撤回本次运行”。运行结束时仍有越界改动的，状态显示“越过了限制”，不会显示为已完成；
任务上的完成标记仍是执行者标的。git 的钩子和配置（`.git/hooks`、`.git/config`）与 Research OS 的备份也在内：
放进一个钩子、删掉一份备份，都算越界。AI 程序在项目里的设置
（`.claude/`、`.opencode/`、`.codex/`、`opencode.json`）也一样：执行者不能写，改了就是越界，
否则下一次运行会读到上一次写下的东西。Claude Code 根本不会加载项目自己的
`.claude/settings*.json`。

**它读不到什么，没有交给它什么。** Claude Code 的读取工具（Read、Glob、Grep、LS）
进不了 Research OS 自己的文件夹（`~/.researchos`）和 `~/.ssh`。执行者程序不会被告知 Research OS
的文件放在哪里；名字像密钥的环境变量（含 `TOKEN`、`SECRET`、`PASSWORD`、`API_KEY`、`AUTH`、
`SESSION`、`COOKIE`，以及 `AWS_*`、`GITHUB_*` 等）不会传给它，程序连接模型必需的除外。
运行记录里会列出没有交给它的变量名字，不列值。

**运行记录。** “运行记录”里能看到执行者说了什么、用了哪些命令和文件、哪些被拒绝、怎样
结束，新建、修改和删除了哪些文件，程序给出的费用，以及发给它的指示。记录里还有执行程序自己的会话编号，
可以据此在那个程序里找到这段对话；Research OS 不会读取、移动或删除这些程序自己的会话记录。记录只留在运行它的这台电脑上，
每个项目保留最近 200 次运行；更早的运行如果还留着撤回时移走的文件，会连同它的记录一起保留，直到你删除这些文件。项目文件超过 50,000 个时，运行前只记录前 50,000 个（数据文件始终会核对），
运行记录会注明，其余文件的改动无法核对，也无法撤回。系统或编辑器留下的文件（如 `.DS_Store`、`~$` 开头的锁文件）不计在内。

**回答、打回、撤回。** 执行者需要你拿主意时，会提出一个问题并停下，任务显示“等你回答”；
点“回答”，它在同一段对话里继续。做得不对就“打回”，写明要改什么；已经标为完成的任务会先
重新打开。只有任务的最近一次运行可以继续。你自己取消一项已有结果的任务的完成勾选、把它改回未完成时，
软件会先问：“这项任务已经有结果。改回未完成后可以再次运行，再次运行会改写同一份结果记录。改回未完成吗？”
勾选完成从不询问。“撤回本次运行”会先列出它将做什么：要放回的文件
（改过或删除的，按运行前的副本恢复，另有它设置的完成标记和结果关联）和要移走的文件
（这次运行新建的，移到这次运行自己的文件夹里；Research OS 不会删除它们，你可以在下面的“运行占用的空间”里删除），
每个文件都带时间和一个勾选框，默认全部勾选；
同时列出撤不回的文件和原因。取消勾选你想保留的文件，再点“确认撤回”；没勾选的文件保持原样，
运行记录里写作“你选择保留”。Python 字节码（`__pycache__`）和 pytest 缓存也会纳入撤回。
本次新建的目录在清空后会移除；运行前就有的目录、运行结束后才创建的目录会保留。运行之后你又改过的文件，或太大（超过 16 MB）
而没有备份的文件，撤不回，会保持原样并说明原因，这时这次运行显示为“部分撤回”。如果之后的运行改过同一些文件，要先撤回之后的那次。
每个项目保留最近 20 次运行的副本（还要在下面的空间上限之内），更早的运行无法再撤回。撤回过的运行会释放自己的副本，
所以不能撤回两次。
本次新建的 `.venv`、`node_modules` 等环境目录，如果运行后没有变化，会整体移入撤回备份。
原有环境会保留，其中安装包等内容的变化不做备份。

**运行占用的空间。** 一个项目的撤回备份里，每份不同的内容只存一份只读副本，需要它的运行共用，
所以几次运行里相同的文件只占一份空间。撤回备份、撤回时移走的文件和运行记录加起来，每个项目默认最多占 5 GB；
可以在“AI 执行者”区、设置时间限制的同一处修改“空间上限”（1 到 100 GB）。超过上限时，Research OS 先释放
最早一次运行的撤回备份，再释放下一次的，这些运行就不能再撤回了；正在运行的、或在等着对比改动的那一次保留自己的备份。
撤回时移走的文件不会被自动清理：它们自己就超过上限时，面板会说明，并说明此后每次新运行的撤回备份在运行结束时就会立刻释放，
在你删除移走的文件之前，新的运行都不能撤回。同一处的“运行占用的空间”按上限列出
“撤回备份”“撤回时移走的文件”和“运行记录”各占多少；列出还留着移走文件的运行，写明任务（任务已不在时写“任务已移除”）、
日期、大小和文件数，每项都有“删除这些文件”；另有“释放所有撤回备份”。这两个按钮都会先问一声，做了就不能反悔。
旧版本留下的撤回备份，会在这个项目第一次整理或打开这个面板时在后台转换，转换期间面板显示“正在整理撤回备份…”。

**记在谁名下。** 执行者新建或修改的每个文件，在“修改历史”里都记为 AI 执行，写明是哪个
执行者、谁启动的运行。结果记录开头有一行，说明是哪个执行者、何时、为谁写的。由 git 管理的
文件，历史以 git 为准，运行记录里会写明执行者做了哪项改动。

**隐私。** Codex 会把它读到的项目内容发送给 OpenAI。DeepSeek Harness 会把它发送给 DeepSeek。Claude Code 会把它读到的项目内容发送给 Anthropic。OpenCode 会把它发送给你在
OpenCode 里配置的模型服务，也可能是这台电脑上的本地服务。Research OS 自己不会把内容发到别处。

**团队里。** 执行者在启动它的人工作的地方干活：PI 的电脑上是正式项目，成员的电脑上是他自己的
工作副本。它写下的是这个人的本地改动，不会自动替你提议；核对结果后，像提交自己的修改一样
“提交修改”。其他成员能看到任务的负责人、结果和修改历史，看不到运行记录。团队里所有人的
Research OS 要先一起更新，再把任务交给 AI 执行者：执行者做完任务后，任务文件里会有一个 `report`
关联，0.2.0 读不了。在有人保存输出目录或登记过程文件之前也要先更新：没有过程文件功能的旧版本，读不了写入了过程文件位置的
`research/folders.json`；一项任务的登记里只要有过程文件，旧版本的视图就会说清单读不了。

**限制。** 这些检查是一道拦栏，不是沙箱：它们按文字检查执行者的命令，执意绕开的执行者
用命令行可以做到。OpenCode 只在运行结束后核对。Codex 使用工作目录写入沙箱，运行结束后核对改动，
没有 Research OS 的逐次工具调用检查。它使用本次运行指定的配置和专用工具，忽略用户
配置和执行规则，不修改 Codex 原有的设置和登录状态。在信任结果之前，请使用已备份的项目副本。

## 保存与审批

研究问题与计划、笔记和结果记录以 Markdown 保存在项目的 `research/` 目录，任务保存在
`research/tasks.json`。保存修改时会保留之前的版本。如果文件同时被别的编辑器修改，
软件会保留当前草稿，并提供“保留草稿”和“重新载入文件”两个选择。
点击“修改历史”可以查看已保存的版本和差异。项目的身份文件暂时读不了（可能还在云端）时，页面会说明，
不列出研究尝试，也只能阅读。

团队成员先保存到自己的工作副本，每份文档和任务清单旁会标出状态：“我的改动，尚未提交”、“提议中”或“已批准，待同步”。
点击“提交修改”后，检查预览、填写说明，再发送给 PI。文档引用的本地文件也会列入预览，可以核对是否需要一起提交；
提交任务时，改动过的任务所关联的结果记录会一起带上，批准后任务不会指向正式项目里没有的记录。PI 批准后才
进入正式项目。PI 的页面上，笔记和结果记录会说明它们随下一次发布交给成员。
不是项目成员的这台 Mac 会说明这一点，只能查看。单人项目保存后直接生效。
